# Casse-Robot

*[English](README.md) · Français*

Prototype d'un jeu de robots en blocs destructibles, dans l'esprit de Robocraft, qui tourne dans le navigateur.

- **Rendu :** Babylon.js 9.28 (`@babylonjs/core`)
- **Physique :** Rapier 0.21 (`@dimforge/rapier3d-compat`, WebAssembly inclus dans le paquet)
- **Langage et outils :** TypeScript, Vite, Vitest

## Jouer en ligne

**https://wasabules.github.io/casse-robot/** : contre l'IA, le garage et l'éditeur de cartes, dans le navigateur (une carte graphique récente et Chrome, Edge ou Firefox de préférence). La page est republiée à chaque envoi sur `main` (`.github/workflows/pages.yml`).

Le multijoueur demande un serveur de jeu (`npm run server`, ou `npm run share` pour le partager sur Internet, voir plus bas) : dans le menu « Multijoueur », indiquer son adresse en `wss://` (une page en https ne peut pas joindre un serveur en `ws://`).

## Lancer le projet

1. Installer **Node.js 20 ou plus récent** : https://nodejs.org (version LTS).
2. Ouvrir un terminal dans ce dossier, puis :

   ```bash
   npm install
   npm run dev
   ```

3. Le navigateur s'ouvre sur `http://localhost:5173`. Chaque fois que tu enregistres un fichier, la page se recharge toute seule.

| Commande | Effet |
|---|---|
| `npm run check` | Vérifie les types et lance les tests : à faire avant chaque commit |
| `npm test` | Lance les tests une fois (`npm run test:watch` pour les relancer à chaque modification) |
| `npm run build` | Version à mettre en ligne, dans `dist/` (`npm run preview` pour la tester) |
| `npm run server` | Lance un serveur de jeu multijoueur (port 8787) ; les joueurs s'y connectent par le menu « Multijoueur » |
| `npm run share` | Partage le jeu sur Internet : compile, lance le serveur et un tunnel Cloudflare, puis affiche le lien à envoyer |
| `npm run battle` | Huit batailles entre IA sans affichage, et un bilan d'équilibrage par robot et par arme (coût d'un pas, temps où les robots sont coincés) ; une autre arène que le Dépôt : `BATTLE_ARENA=canyon npm run battle` |
| `npm run bench` | Coût d'un pas de simulation à douze robots, étape par étape |
| `npm run perf` | Mesure du rendu : le jeu construit dans Chrome sans fenêtre sur ta carte graphique, une bataille à douze robots, le temps d'une image étape par étape (`--compare` pour un avant/après) |
| `npm run render:check` | Essai du rendu (aussi dans l'intégration continue) : chaque écran se dessine, sans erreur, et survit à une réinitialisation de la carte graphique |
| `npm run map:check` | Vérifie les cartes communautaires (celles de `maps/`, ou les fichiers donnés : `npm run map:check -- ma-carte.casse-map.json`) |
| `npm run map:terrain` | Importe un relief (PNG 16 bits, RAW 16 bits) dans une carte : voir `docs/maps.md` (en anglais) |
| `npm run map:export -- all` | Écrit les arènes du jeu en fichiers de carte (`content/arenas/`) |
| `npm run map:pack`, `npm run map:unpack` | Fait d'un fichier de carte un paquet (un dossier : `map.json`, un `terrain.png` en 16 bits, `LICENSE.txt`), et l'inverse |
| `npm run schemas` | Refait d'après le code les schémas JSON des formats des cartes et des robots (`schemas/`) et le catalogue du jeu en données (`content/`) |
| `npm run models` | Vérifie les modèles glTF des accessoires (`public/models/props/`) et met leur manifeste à jour : voir `docs/models.md` (en anglais) |

## Langues

Le jeu parle **français** et **anglais** : la langue se choisit dans **Paramètres → Profil → Langue** (par défaut, celle du navigateur ; l'anglais pour une langue que le jeu ne connaît pas encore), et tout l'écran change aussitôt, sans recharger la page. Les noms des robots, des arènes, des pièces et des armes se traduisent aussi ; les touches qui écrivent un caractère gardent le nom de ton clavier (Z sur un clavier AZERTY).

**Pour les traductrices et les traducteurs :** chaque langue est un dossier de `src/client/i18n/locales/` (le français, `fr/`, est la langue source ; l'anglais, `en/`, le meilleur point de départ), un fichier par partie du jeu (menus, HUD, garage, fiches des pièces…). Pour une nouvelle langue, copie `en/` dans un dossier à son code (`de/`, `es/`…), traduis les textes (jamais les clés ni les `{paramètres}` entre accolades ; les pluriels selon les règles de ta langue), puis déclare-la dans `src/client/i18n/state.ts` et `src/client/i18n/locales/index.ts`. TypeScript signale toute clé oubliée ou en trop et tout paramètre différent du français, et `npm run check` vérifie le reste ; une langue encore incomplète s'affiche en anglais là où il manque une traduction. Le détail (glossaire, conventions) est dans `docs/architecture.md`, section « Langues (i18n) ».

## Cartes communautaires

Chacun peut faire sa carte, **dans le jeu, avec l'éditeur de cartes** (menu principal → **Éditeur de cartes**), ou à la main : un relief importé de son outil de terrain (Gaea, World Machine, Blender, terrain.party, Unity : une image PNG 16 bits ou un RAW 16 bits), et des éléments de jeu décrits dans un fichier JSON (`.casse-map.json`) : bâtiments qui s'effondrent, bois, rochers, murets, ponts, conteneurs, eau (profonde ou non), lave, chemins, zones à capturer, lieux nommés. Le jeu la vérifie (lignes de départ dégagées, zones que l'IA atteint, nombre d'éléments raisonnable), puis la joue comme ses propres arènes : l'IA s'y déplace, la mini-carte la dessine.

- **L'éditeur de cartes :** on y part d'une carte vierge, d'une carte de la bibliothèque (« Modifier ») ou d'un fichier ; on importe un relief (une image) et on le sculpte au pinceau (monter, creuser, lisser, aplanir) ; on pose les éléments de jeu d'une palette (maisons, immeubles, bois, rochers, rampes, conteneurs, accessoires, décor, zones, lieux, fumerolles, cascades, lacs de lave), on trace chemins, clôtures, coulées de lave et ponts point par point ; la carte peut être de nuit (Réglages → Nuit : la lune, les étoiles, les lampadaires et les mâts d'éclairage allumés) ; on règle l'eau, le ciel, le sol, les limites, et on place librement les lignes de départ des deux équipes. Ce qu'on voit est ce qu'on joue, avec les problèmes de la carte là où ils sont ; **P** l'essaie aussitôt contre l'IA, et la pause ramène à l'éditeur, au même état. Annuler et rétablir, un brouillon gardé à chaque modification, l'enregistrement dans la bibliothèque, l'export en `.casse-map.json` et du relief en PNG 16 bits. Le détail : [`docs/maps.md` (en anglais)](docs/cartes.md#léditeur).
- **Jouer une carte :** **Jouer → un mode → la carte** (celles de `maps/` sont livrées avec le jeu). **Cartes communautaires… → Importer une carte…** en ajoute une, gardée dans le navigateur ; on peut aussi l'exporter ou la supprimer.
- **En multijoueur :** le serveur (`npm run server`) met les cartes de `maps/` dans sa rotation (`MAPS_DIR` pour un autre dossier, `MAPS_ONLY=1` pour ne jouer qu'elles) ; un joueur qui n'a pas la carte la reçoit une fois, et la garde.
- **En faire une :** le guide complet (le format champ par champ, l'import d'un relief, les limites, les tests, comment proposer sa carte au jeu par une *pull request*) est dans [`docs/maps.md` (en anglais)](docs/maps.md). L'exemple : `maps/val-du-lac.casse-map.json` (« Val du Lac » : un lac, une rivière et son vieux pont, un village, une ferme, une ruine), et le script qui l'a faite, `tools/maps/example.ts`. Un [schéma JSON](schemas/map.schema.json) donne l'autocomplétion et la vérification dans son éditeur de texte (`"$schema"` : voir le guide) ; les plans des robots ont [le leur](schemas/robot.schema.json). Les arènes du jeu elles-mêmes sont écrites dans le même format dans `content/arenas/` (du Dépôt au Port) : un point de départ, ou un exemple de ce que le format sait dire.

## Modèles 3D et données ouvertes

- **Des modèles 3D sans code :** chaque accessoire du décor (caisse, baril, arbre, mur, voiture, lampadaire…) peut recevoir un modèle glTF fait dans Blender : l'enregistrer sous `public/models/props/<type>.glb`, lancer `npm run models`, et le jeu l'emploie à la place du modèle qu'il dessine (la caisse livrée avec le jeu en est un exemple). Les conventions sont dans [`docs/models.md` (en anglais)](docs/models.md).
- **Les éléments du jeu en données :** [`content/catalog.json`](content/catalog.json) donne chaque bloc, forme, roue, arme, arme de contact, accessoire et robot prédéfini avec ses chiffres et ses noms en français et en anglais, décrits champ par champ par [son schéma JSON](content/catalog.schema.json) : pour vos outils, wikis et tableurs. Il est fait d'après le code (`npm run schemas`).

## Chargement

Au démarrage, un écran de chargement prépare tout avant le menu : la physique, tous les sons, la musique (plusieurs morceaux par écran, douze en partie, enchaînés en fondu sans qu'aucun ne revienne avant que tous soient passés ; celle de l'accueil part dès le premier clic, sans attendre) et les effets. Avant chaque partie, un autre écran construit l'arène et les robots, prépare les effets et la musique de la partie, et la partie ne commence qu'ensuite : pas de saccade au premier tir ni à la première explosion.

## Jouer à plusieurs sur Internet

Il faut `cloudflared` (gratuit, sans compte : `winget install --id Cloudflare.cloudflared` sous Windows). Puis :

```bash
npm run share
```

Le jeu se compile, le serveur de jeu démarre (il sert aussi la page) et un tunnel Cloudflare s'ouvre : un lien `https://….trycloudflare.com` s'affiche. Envoie-le à tes amis ; chacun (toi compris) l'ouvre, choisit **Multijoueur** puis **Choisir mon robot et rejoindre** : l'adresse du serveur est trouvée toute seule. La machine qui lance `npm run share` héberge la partie : elle doit rester allumée, et chaque joueur reçoit environ 180 Ko/s. Le lien change à chaque lancement ; Ctrl+C arrête tout. Sur le même réseau, l'adresse « Réseau local » affichée suffit (sans tunnel). `npm run share -- --no-build` repart sans recompiler.

## Ce qui existe

**Jouer**
- **Bataille** : tu pilotes un robot dans l'équipe bleue, six contre six ; la première équipe à quinze destructions gagne, les robots détruits réapparaissent de leur côté. **Capture de zones** : prends et tiens les zones A, B et C ; chaque zone tenue rapporte des points, la première équipe à cent gagne. **Roi de la colline** : une seule zone en jeu, qui se déplace toutes les quarante secondes ; la première équipe à soixante gagne. **Élimination** : sans réapparition. **Arène libre** : tu regardes deux équipes s'affronter et tu tires depuis une caméra libre. **Stand de tir** : les robots ne tirent pas.
- Dix arènes au choix, et les **cartes communautaires** (voir plus haut ; le **Val du Lac** est livré avec le jeu) : le **Dépôt** (piliers, rampes, barils explosifs), la **Forteresse** (une plateforme au centre, quatre rampes pour y monter), les **Tranchées** (trois couloirs séparés par des murets), le **Chantier** (deux terrasses sur les flancs, des conteneurs au centre) et la **Vallée**, une grande carte de plus de 200 m entourée de montagnes : du relief, une rivière qu'enjambe un pont de pierre, un village, un fort sur sa colline, une usine et ses citernes, un aérodrome, des bois. Tout s'y abat : les murs tombent par pans, les toits s'effondrent quand leurs murs ont cédé, les arbres basculent, les citernes explosent en chaîne. Et deux autres aussi grandes : le **Canyon**, un désert rouge coupé par un canyon aux parois à pic, où l'on descend par des sentiers taillés dans la falaise, qu'on franchit par un viaduc de bois ou par une arche naturelle au sommet d'une mesa ; une voie ferrée qui traverse deux buttes en tunnel, une ville de l'Ouest en bois (saloon, église, château d'eau, gare), une mine (chevalement, terrils, wagonnets), une oasis au fond du canyon, des cactus. Et l'**Île volcanique** : une île tropicale cernée par la mer (on s'y noie), dominée par un volcan dont le cratère bouillonne de lave ; deux routes en lacets y montent ; des coulées de lave (qui brûlent) descendent jusqu'à la mer, coupées d'un gué de basalte ; deux gorges, avec leur cascade, se passent sur des ponts de bois ; un village de pêcheurs et ses cases sur pilotis, des bunkers face au large, une piste en herbe, l'épave d'un cargo sur la plage, et la jungle (palmiers, fromagers), qui brûle. Et la **Cité**, une ville en ruines pour le combat urbain : des rues et de longues avenues autour d'une grande place et de son monument, une voie rapide surélevée sur ses piles, une gare dont les voies courent au fond d'une tranchée, un parc sur sa butte, une tour en ruine et un parking à étage ; ses immeubles s'effondrent étage par étage, et ses voitures abandonnées prennent feu puis explosent. La **Cité de nuit** est la même ville sous la lune et les étoiles : ses lampadaires et des mâts d'éclairage allumés (on les abat pour plonger une rue dans le noir), des fenêtres éclairées, et des rues sombres où ce sont les tirs, les explosions, les leurres, les incendies et les phares des robots qui éclairent les façades. Et le **Port**, au bord de la mer : un cargo à quai où l'on monte par ses passerelles (une zone sur son pont), des portiques à conteneurs, un terminal en dédale, un pont tournant sur le chenal, une darse, des dépôts pétroliers dont les citernes sautent en chaîne, des entrepôts qu'on traverse, la voie ferrée, le quai bas des pêcheurs et les phares ; l'eau y est profonde, qui y tombe se noie. En capture de zones, cinq zones à prendre dans les cinq grandes arènes.
- **Multijoueur** : lance `npm run server` sur une machine (ou `npm run share` pour jouer sur Internet, voir plus haut), puis choisis « Multijoueur » au menu (l'adresse par défaut est celle du serveur qui sert la page, ou en développement la machine qui sert la page, port 8787). Les joueurs remplacent des robots de l'IA dans une bataille six contre six sans fin, qui change d'arène à chaque partie ; le serveur fait autorité. Il garde aussi la progression de chacun (fichier `casse-robot-progress.json`) : crédits gagnés sur ce serveur, pièces qu'on y débloque en rejoignant avec un robot du garage.
- Les commandes reprennent celles de **Robocraft** (touches par défaut ; ZQSD sur un clavier AZERTY, WASD sur un QWERTY). Par défaut, **la caméra dirige** : au sol, ZQSD donnent une direction à l'écran et le robot y va (Z : là où l'on regarde) ; un robot volant se tourne vers où regarde la caméra ; un **avion va là où l'on regarde** (à la souris : il s'incline et tire de lui-même ; regarder vers le haut et continuer le fait **boucler**, passer sur le dos et revenir), ses **gaz à part** sur Z et S (une vitesse voulue, que montre le panneau de vol ; Maj : plein gaz, X : coupés), et au clavier Q et D le font virer, Espace et C cabrer et piquer (tenu : une boucle aussi). Un réglage (« Direction », « En avion ») rend la conduite de char au clavier, et le pilotage **manuel** (le manche au clavier, sans aide : Espace et C cabrent et piquent, Q et D roulent, A et E sont le palonnier, Z et S les gaz ; V bascule en vol). La souris vise (les tourelles suivent), clic pour tirer, 1 à 9 pour changer d'arme (une **toupie**, une **lame laser**, une **scie** ou une **foreuse** choisie monte en régime d'elle-même, un **marteau**, un **fouet** ou une **lance** frappe à la gâchette ; un **champ broyeur** n'a pas de touche : il s'arme seul), **Espace pour freiner** au sol (les roues et les chenilles freinent sans déraper ni faire basculer le robot, patins et pattes s'arrêtent), Espace et C pour monter et descendre en vol (relâchées, le robot s'arrête où il est), **Maj pour le boost** (propulseurs à fond et moteurs des roues au sprint ; il ne freine jamais). Toutes les touches se changent dans les paramètres, celles du garage comprises, et chaque aide, chaque fiche nomme celles que tu as choisies. Une **manette** (Xbox, PlayStation) se branche quand on veut : stick gauche pour conduire (en avion : gaz et virage), stick droit pour la caméra (en avion : la direction), gâchettes pour viser et tirer, des boutons pour le reste ; elle parcourt aussi les menus. L'écran ne garde que l'essentiel (score, armes, état du robot, mini-carte) : **Tab** ouvre le tableau des robots des deux équipes (état, destructions et morts), de la partie et des commandes (tenu, ou d'un simple appui pour l'épingler), et **M** la carte entière. Tous les robots se pilotent, l'avion compris ; en vol, **A et E** commandent le lacet, indépendamment du roulis : un drone, un hélicoptère pivotent sur place en restant à plat, un avion vire à plat au palonnier, ailes à l'horizontale, sans glisser de côté (les mines télécommandées passent alors sur G). Au-delà de la limite de l'arène, l'avion fait demi-tour de lui-même. Sur un écran tactile : un manche, des boutons de tir et de vol, et un réticule ; un bouton de pause et le plein écran (là où le navigateur le permet), une invitation à tourner le téléphone à l'horizontale, et un HUD qui laisse la place aux pouces. Les menus et les écrans de choix du robot et de l'arène se manient au doigt, en hauteur comme à l'horizontale, et le premier lancement sur un téléphone prend les graphismes les plus légers. Le garage et l'éditeur de cartes sont faits pour la souris : au doigt, ils s'ouvrent, se quittent, et disent ce qui demande une souris.
- Un **garage** pour construire ton robot bloc par bloc (symétrie, orientation ; roues fixes, directrices ou roulettes folles, trois pièces à part, la directrice plus chère ; des roues sur les flancs ou sous un bloc ; des chenilles qu'on empile pour les faire plus hautes ou plus larges, d'une seule bande), dans un budget de 600 points, avec des **blocs de forme** (biseaux, coins, coins rentrants, arrondis, pentes douces, demi-blocs, en blindage léger ou normal, biseau et coin aussi en lourd), qui ont la forme qu'on voit pour la physique : une rampe fait monter, un nez en biseau dévie les chocs. Une tourelle, une forme, un lance-leurres s'orientent d'eux-mêmes selon la face où on les pose (sous un bloc, une tourelle pend ; sur un flanc, elle sort de côté) ; R fait pivoter, Maj + R bascule, O coupe l'orientation automatique (comme tous les raccourcis du garage, ils se changent dans les paramètres, et Ctrl+Z annule sur un clavier AZERTY comme QWERTY), et un aperçu montre le bloc tel qu'il sera posé (flèche jaune : le sens de la poussée d'un moteur). Il y a aussi annuler et rétablir, une vue par étage, le copier-coller d'un étage ou d'une zone (Maj + clic sur deux blocs), des roues qu'on peut décaler d'une demi-case et le centre de masse affiché ; pour un robot volant, sa portance et son autonomie. Les pièces sont dans un **inventaire** : des catégories en onglets, une recherche (« / »), des vignettes 3D, et la fiche de chaque pièce (à quoi elle sert, ses caractéristiques, son aperçu qui tourne) ; 1 à 9 reprennent les pièces récentes, et le clic du milieu copie la pièce visée, orientation comprise : chaque clic gauche en pose le double. Au sol, une flèche « AVANT » et les côtés du robot, et une boussole à l'écran, disent toujours où est l'avant. Tu l'essaies, tu l'enregistres, tu le choisis pour la bataille. On ne peut pas poser une pièce qui en gênerait une autre : un bloc devant le canon d'une tourelle, dans le disque d'une hélice ou les pales d'un rotor, sur une roue, contre la nacelle d'un turboréacteur ou une patte, sous une soute à bombes ou derrière un poseur de mines (ni l'inverse) ; l'aperçu passe au rouge, avec en transparence ce que la pièce occupe et ce qu'elle gênerait, et le garage dit pourquoi (« Gêne le canon (Tourelle mitrailleuse) »). Une tourelle ne réserve que sa pose de repos, canon droit devant : un bloc à côté de sa tête borne seulement son champ de tir. Les hélices, rotors, nacelles et pattes sont dessinés au garage, dans l'aperçu et les vignettes comme en jeu.
- Un **écran de choix du robot** : une grille de tous les robots (les tiens d'abord) sur toute la largeur de l'écran, chaque carte avec sa vignette, sa propulsion, ses armes et son coût ; des filtres (roues, chenilles, pattes, patins, volants, avions, ton garage), une recherche et un tri ; et la fiche du robot sélectionné (à côté de la grille, au-dessus sur un téléphone), avec son aperçu en 3D qui tourne, sa masse, sa vitesse et ses armes. Le dernier robot choisi est mis en avant. Au clavier : les flèches parcourent la grille, Entrée choisit ; à la manette aussi. Et un **écran de choix de l'arène** du même genre : chaque arène, et chaque carte communautaire, avec son plan vu de dessus (relief, eau, lave, bâtiments et arbres, lignes de départ des deux équipes, zones à capturer), sa description et quelques faits (taille, zones, jour ou nuit), et « Au hasard ».
- Des sons synthétisés et placés dans l'espace : tirs, explosions, chocs, moteurs ; un marqueur et un son quand tes tirs touchent, un arc vers qui te tire.
- Un **lecteur de musique** : chaque morceau a son titre (« Titans d'acier », « Néon blindé »…) ; quand il commence, un mot discret l'affiche quelques secondes. Dans les menus et au garage, une ligne « en écoute » avec ses boutons **précédent et suivant** (aussi dans Paramètres → Son) ; en partie, **Pg suiv.** et **Pg préc.** passent au morceau suivant ou reviennent au précédent (des touches qu'on peut changer). Le précédent remonte les morceaux entendus sur cet écran, puis le suivant y repart.
- Une **progression** : chaque partie pilotée rapporte des crédits (davantage pour une victoire, des destructions, des zones prises), qui débloquent des pièces au garage ; les pièces de base sont gratuites. Un réglage « Toutes les pièces » ouvre tout le garage (bac à sable).
- Un écran **Paramètres** (depuis le menu principal ou la pause), appliqués tout de suite et gardés dans le navigateur. Graphismes : le moteur de rendu (WebGL, ou **WebGPU** si le navigateur l'offre ; pris au chargement de la page), préréglage bas, moyen ou haut, ombres et leur finesse, échelle de rendu, effets réduits, fumée et flammes réalistes ou simples, champ de vision, compteur d'images par seconde. Contrôles : sensibilité de la souris, axes inversés, viseur à maintenir ou à bascule, direction à la caméra ou au clavier, pilotage de l'avion à la souris ou manuel, la manette (vitesse et axes du stick droit, zone morte), et **ses propres touches** : une ligne par action (au sol, en vol, armes, interface, caméra libre, garage), deux touches au clavier ou à la souris et un bouton de manette ; on clique une case, puis on appuie sur la nouvelle touche (Échap annule, clic droit retire ; au garage, une combinaison comme Ctrl+Z ou Maj+R) ; une touche déjà prise au même moment passe à l'autre action en échange, et ↺ remet celles par défaut. Les aides du jeu nomment les touches choisies, selon le clavier (Z sur un clavier AZERTY). Son : activé, volume. Profil : la langue du jeu (français ou anglais), nom et serveur multijoueur.

**Les robots**
- Chaque arme a sa précision : meilleure au viseur et à l'arrêt, dégradée en roulant, en virant ou en tanguant (un sniper qui bouge ne touche plus rien) ; le réticule montre le cercle où partiront les tirs. La lunette du sniper a son optique ; au canon (et aux lanceurs d'obus IEM et de fumigènes), c'est le joueur qui choisit la hausse en levant la souris : le canon pointe droit vers le réticule, la portée dépend de la hausse, et un losange marque le point de chute prévu ; son panneau indique la hausse, le cap, la portée et le temps de vol ; les robots volants ont un horizon artificiel, l'altitude, la vitesse et le cap.
- Vingt-huit armes, dont le **laser** (tir continu et précis, qui passe le blindage lourd), le **canon électrique** (un trait qui traverse plusieurs blocs) et le **plasma** (un jet brûlant à courte portée) : ces trois-là puisent dans les batteries du robot. Le **fusil à pompe** tire une gerbe de neuf plombs, dévastatrice au contact ; le **lance-roquettes** vide son panier en une salve de mini-missiles qui partent en éventail et convergent sur le point visé ; les **missiles à verrou** ne partent qu'une fois l'ennemi gardé 1,2 s dans le viseur et en vue (le décor ou la fumée qui le cachent font perdre le verrou), puis le poursuivent avec de l'élan et du poids : tirés vers le haut, ils passent par-dessus un mur ou une colline et plongent sur lui, et un écart franc au bon moment les fait rater ; tout missile part d'abord droit dans l'axe de son arme avant de tourner ; l'**ogive pilotée**, un seul coup par vie, se dirige à la souris, la caméra à son nez, et explose d'un clic (ou au contact) avec un souffle énorme, pendant que son robot attend, immobile. Chaque tir recule : la tête de la tourelle part en arrière, et la vue du pilote saute vers le haut puis revient. Sous un avion, une **soute à bombes** lâche un chapelet de bombes tant qu'on tient la gâchette : elles tombent en gardant la vitesse de l'avion, en sifflant, et un cercle au sol montre où tombera la prochaine. Un **bouclier** absorbe une partie des dégâts autour de lui tant que les batteries tiennent. Neuf **mines**, posées derrière soi : classique, IEM (paralyse), incendiaire, fumigène, bondissante (éclate à hauteur de caisse), anti-aérienne (tire un missile sur ce qui passe au-dessus), télécommandée (E la fait sauter), capteur (fait voir les ennemis proches à son équipe, à travers les murs) et ventouse (se colle au robot et éclate deux secondes plus tard), chacune avec son propre modèle et un voyant qui clignote à son rythme une fois posée ; une explosion fait sauter les mines voisines en chaîne, et l'IA contourne celles qu'elle a repérées. Le **rayon réparateur** remet en état les alliés, et vole la vie des ennemis ; les **nanites** verrouillent seules l'allié le plus abîmé et le réparent de loin, sans qu'on vise ; le **projecteur de bouclier** déploie devant soi un mur d'énergie qui arrête les tirs ennemis ; et la réparation (module, rayon, nanites) fait **repousser les blocs perdus**. Un **lance-leurres** (touche F par défaut ; l'IA s'en sert seule) éjecte des leurres brûlants qui détournent les missiles ennemis ; et les missiles, roquettes, bombes, mines et l'ogive pilotée s'abattent en vol : on les vise au réticule, et les tourelles automatiques de l'IA tirent sur ceux qui foncent sur elle.
- Des tirs qui se voient : les missiles laissent une traînée de fumée qui dessine leur course (grise pour l'anti-aérien, dont l'éclatement laisse un nuage noir ; épaisse pour l'ogive ; fine pour les roquettes, dont on voit l'éventail se refermer), un missile abattu part en vrille, un missile leurré file perdu en crachotant ; le sniper laisse un sillage de vapeur, le canon électrique un trait ionisé qui crépite ; une balle de fusil sur quatre est une traçante à la couleur de l'équipe ; les douilles sautent de la culasse, la bouche fume après un coup lourd, le canon soulève la poussière autour du robot, le lance-missiles crache un panache vers l'arrière ; le laser et le plasma font rougeoyer ce qu'ils touchent ; le rayon réparateur montre la vie qu'il vole (des filets rouges vers le tireur) et celle qu'il rend (des filets verts vers l'allié), et les nanites volent en nuée.
- Des **armes de contact** : une masse qui tourne a des conséquences. La **toupie horizontale** (une barre d'acier de 1,9 m qui tourne à plat devant le robot) monte en régime en 2,4 s en puisant dans les batteries, garde son énergie et la vide dans ce qu'elle frappe : elle arrache des blocs entiers, rompt les bras fragiles et projette sa cible, mais chaque coup lui coûte du régime et fait rebondir son propre robot ; lancée, elle le rend gyroscopique (il se cabre ou pique quand il roule sur le côté), et sous la moitié de ses points elle se déséquilibre : tout le robot vibre, sa visée et ses roues en souffrent, et elle s'use jusqu'à casser. Un glacis en biseau pris en biais la fait glisser, le blindage lourd l'encaisse, un robot bas passe dessous. Le **marteau pneumatique** s'abat devant le robot à la gâchette, frappe fort le dessus de sa cible et lui soulève le nez à chaque coup. Une jauge autour du réticule montre le régime ou le réarmement ; étincelles, éclats, sifflement qui monte avec le régime, claquement au coup. L'IA charge à plein régime et frappe quand sa tête toucherait. Et des **armes d'énergie**, sans masse : ni gyroscope, ni recul, ni balourd, mais elles vident les batteries. La **lame laser** (un arc qui balaie à plat devant le robot, en bourdonnant) s'allume en une demi-seconde et découpe vite, à petits coups, ce que le blindage lourd ne freine pas ; sous une IEM ou dans l'eau, elle s'éteint d'un coup. Le **fouet plasma** claque de droite à gauche devant le robot et met le feu à ce qu'il touche. La **lance électrique** sort droit devant et paralyse les organes autour du point touché pendant 2,5 s (les roues de ce côté en roue libre, une tourelle muette, un moteur coupé : le reste marche ; des arcs courent dessus, et le HUD dit ce qui est coupé). Le **champ broyeur** s'arme seul quand un ennemi approche : ce qui touche la coque est frappé et repoussé, et une toupie ennemie qui s'y frotte perd son régime. La **scie circulaire** et la **foreuse** ne frappent pas : elles mordent en continu ce qu'elles touchent, leurs dégâts suivent leur régime, qui baisse sous la charge, et elles percent un bloc puis le suivant. La scie, petite et rapide, accroche : sa prise tire le robot le long de sa cible, on la conduit en la longeant ; un glacis rasant la fait glisser. La foreuse, une mèche d'un mètre derrière un réducteur, traverse une ligne de blocs jusqu'au cockpit ; son couple tord sa cible et, en réaction, fait rouler sur lui-même un robot léger : il lui faut de la masse ou des appuis larges. Gerbes d'étincelles, copeaux de métal, entaille rouge qui se refroidit ; la scie siffle et grince en mordant, la foreuse gronde. L'IA vise le cockpit avec la foreuse et pousse droit, et longe sa cible avec la scie. Et des **frappes à mécanique** : le **flipper** relève d'un coup de vérin un plateau en coin glissé sous l'ennemi et le jette en l'air (il se fait mal en retombant) ; le sol retient celui qui soulève, mais un robot léger qui veut soulever un lourd s'enfonce et pique du nez. Le **fléau** fait tourner une boule hérissée au bout d'une chaîne : un vrai pendule, qui frappe d'autant plus fort qu'il va vite (quatre fois plus à deux fois la vitesse), suit mal les virages et tire sur son robot à chaque tour, rebondit et s'enroule autour d'un poteau. La **mâchoire broyeuse** saisit ce qui entre dans sa gueule, l'écrase et le traîne à reculons ; c'est le plus lourd qui ne bouge pas : un robot léger qui en mord un lourd ne fait que s'y accrocher. Elle lâche quand on relâche la gâchette, au bout de six secondes, ou quand la proie tire trop fort. Et la famille des toupies : la **toupie verticale** (un disque épais debout à l'avant) cueille l'adversaire par-dessous, le soulève et le retourne ; si elle pique du nez et mord le sol, c'est son propre robot qui part en salto arrière ; le **tambour**, bas et large, fait sautiller sa cible à petits coups et lui arrache roues et galets ; l'**anneau-coque** tourne autour du robot entier, frappe de tous côtés sans viser et lui sert de blindage, mais fait de lui un énorme gyroscope qui dérape quand l'anneau reprend de la vitesse. Et l'**hélice** d'un avion est tranchante : son disque de 2 m blesse ce qu'il frôle, mais s'y brise, et le moteur avec. Les lames et les têtes des armes de contact se touchent : un tir sur la barre, le disque ou l'anneau frappe l'arme.
- 46 robots prédéfinis, dont la Faucheuse (toupie horizontale), le Pilon (marteau pneumatique), le Duelliste (lame laser et lance électrique), l'Oursin (champ broyeur et fouet plasma), le Scieur (scie circulaire), le Foreur (foreuse, sur un large châssis à chenilles), la Catapulte (flipper), le Broyeur (mâchoire broyeuse), le Batteur (fléau), le Culbuteur (toupie verticale), le Tambourin (tambour) et le Tourbillon (anneau-coque), trois vaisseaux taillés dans les blocs de forme : la Frégate (vaisseau en flèche sur quatre réacteurs, laser ventral), la Raie (aéroglisseur profilé, roquettes et lance-flammes) et le Bastion (char lourd à glacis en biseau et jupes inclinées) ; et aussi : engins à roues suspendues, fixes ou directrices (épure d'Ackermann), char à chenilles, aéroglisseur sur patins anti-gravité, araignée sur six pattes articulées, drone et hexacoptère à rotors, hélicoptère à rotor orientable et rotor de queue, avion à ailes et gouvernes, voiture-fusée, caisson à bouclier et laser (Rempart), chasseur au canon électrique (Lancier), et ceux des nouvelles armes : Cogneur (fusils à pompe, il charge), Essaim (roquettes), Traqueur (missiles à verrou et radar), Brasier (plasma), Porte-ogive (ogive pilotée), Bombardier (soutes à bombes : l'IA fait des passes sur ses cibles), et des classes : Sapeur (mines IEM, ventouses et bondissantes semées autour de sa cible), Mécano (soigne ses alliés en tournant autour d'eux), Gardien (mur d'énergie et rayon réparateur), Ange (drone aux nanites), Guetteur (capteurs et mines anti-aériennes), Chasseur (deux turboréacteurs) et Bolide (quatre turboréacteurs sur roues). Les avions ont de vraies hélices, qui tournent selon les gaz ; le **turboréacteur**, qu'on pose où l'on veut et dans le sens qu'on veut, pousse cinq fois plus fort qu'un propulseur, avec une longue flamme de postcombustion.
- Une vraie physique de propulsion : couple et charge des roues, suspension, poussée des rotors, portance des ailes, et de l'énergie : les réacteurs vident les batteries, un drone doit se poser pour recharger.
- Des blocs plus ou moins durs, avec des résistances : le blindage lourd encaisse les balles, le blindage réactif les explosions. Les cols fins et les bras d'un seul bloc peuvent casser sous un choc. Les chocs abîment : percuter un mur à pleine vitesse, ou un robot léger, coûte des blocs.
- Un robot est hors de combat quand son cockpit est détruit, ou quand il n'en reste plus qu'un quart autour de lui. Renversé, le gyroscope du cockpit le remet d'aplomb au bout de trois secondes.
- Des dégâts qui se voient : les blocs abîmés roussissent, se tachent et fument, noircissent de suie après un feu ou une explosion ; batteries et boucliers touchés crépitent ; un robot à bout flambe, ses morceaux arrachés fument en volant et son épave laisse une colonne de fumée ; les roues abîmées fument, leurs épaves brûlent ; un canon qui chauffe rougeoie puis fume. Au sol : traces de pneus et de chenilles qui s'effacent, poussière au dérapage, gerbes d'eau dans la rivière, empreintes et poussière des pattes, anneau de poussière à un atterrissage lourd, étincelles des chocs.
- Des équipements : batteries, module de réparation, radar (il voit à travers les murs), brouilleur, et des lumières, qu'on pose dessus, dessous ou sur un flanc : le **phare**, qui éclaire droit devant la face où on le pose, la **balise lumineuse**, qui luit de la couleur de son équipe, les feux d'avion (le **feu de position**, rouge à gauche et vert à droite, le **feu à éclats**, un stroboscope blanc, le **feu anticollision**, rouge, qui tourne), le **gyrophare** orange, dont le faisceau balaie les murs, et la **rampe de police**, bleue et rouge en alternance. Elles brillent de jour comme de nuit, et la nuit, elles éclairent ce qui les entoure. Le Camion et le Bélier roulent phares allumés, le Drone porte une balise.
- Des moteurs qu'on abîme : un moteur touché perd de sa poussée, a des ratés, fume, puis crache une fumée noire et peut prendre feu ; un avion au moteur à bout plane et se pose.
- Des moteurs qui brûlent : derrière la tuyère d'un réacteur, d'un propulseur ou d'un turboréacteur qui pousse, un jet de flamme (1 m pour un réacteur, plus de 4 m pour un turboréacteur en postcombustion) chauffe ce qu'il touche : les blocs et les roues d'un robot ennemi (qui peuvent prendre feu), ceux de son propre robot s'il est mal construit (le garage avertit d'un bloc posé dans le jet d'un moteur), le bois du décor, qui s'embrase, un baril, qui saute. Un Bolide qui fuit brûle son poursuivant, et l'IA d'un robot à propulseurs les allume sur un ennemi collé à son arrière. Là où le jet frappe, des flammèches s'étalent, la surface rougeoie, le sol roussit et les blocs noircissent de suie.
- Des effets de vol : postcombustion, traînées de condensation, tourbillons de bout d'aile, poussière soulevée par les rotors, disque flou des hélices, échappement des robots qui accélèrent, arcs électriques d'un robot paralysé, avion abattu qui tombe en fumant.

**Le combat**
- De la fumée et des flammes réalistes (réglage « Fumée et flammes » : réalistes, sauf au préréglage bas) : la fumée est faite de volutes texturées, éclairées par le soleil (côté soleil plus clair, dessous plus sombre), qui roulent, s'effilochent et s'effacent au ras du sol ; un fumigène fait un vrai nuage épais qui déborde et cache ce qu'il cache (de dedans, on n'y voit pas à plus de quelques mètres) ; les flammes ondulent en montant, du blanc-jaune au rouge ; une explosion est une boule de feu qui roule, noircit en fumée et projette la terre ; le lance-flammes crache un jet de feu ; la flamme des moteurs file et tremble, bleutée au cœur pour un turboréacteur en postcombustion.
- Le décor réagit : le bois (cabanes, toits, arbres, caisses) prend feu, noircit, gagne ses voisins et s'effondre ; le lance-flammes et la mine incendiaire laissent au sol des flaques de feu (l'eau les éteint) ; une explosion laisse un cratère, une brûlure, une fumée qui monte encore, des braises qui retombent, et fait ployer les arbres ; une bouteille percée crache son gaz, la mèche d'un baril crépite, des ruines fument. En option (onglet Graphismes) : un halo autour de ce qui brille, des **lumières dynamiques** (des dizaines à la fois, si la carte graphique le permet : les explosions, les coups de feu, les missiles, les traçantes, les leurres, le plasma, les feux, les flammes des moteurs et les armes d'énergie éclairent le sol et les murs autour d'eux ; la nuit, ça se voit) et l'air qui tremble au-dessus des feux et derrière les tuyères.
- 9 armes à projectiles physiques, sur des tourelles indépendantes du robot : fusil automatique (surchauffe), sniper perforant, canon, missile téléguidé, missile anti-aérien, mine, lance-flammes (le feu se propage), canon à impulsion électromagnétique (il coupe moteurs et tourelles : un drone tombe), fumigène (il coupe la vue). Chargeurs, balistique, recul, perforation, explosions. Plusieurs armes identiques tirent à tour de rôle, de plus en plus vite, mais chaque arme de plus accélère moins la cadence que la précédente (deux fusils : ×1,8, quatre : ×2,95).
- L'IA combat à la portée de ses armes (le lance-flammes au contact, le sniper de loin) en tournant autour de son adversaire, se met à l'abri derrière un pilier pour recharger ou se réparer, achève les robots abîmés et choisit ses cibles selon ce que ses armes percent. Elle contourne les obstacles, ne vise que ce que son équipe a repéré (à vue ou au radar), se pose pour recharger ses batteries, couvre sa retraite avec un fumigène, et vise moins bien une cible qui manœuvre.
- Le fil des destructions dit qui a détruit qui, et avec quoi.
- Des arènes de 72 × 72 m avec des rampes, des piliers, et des accessoires : caisses, barils explosifs (en chaîne), bouteilles de gaz qui s'envolent quand on les perce ; la Vallée et le Canyon, avec leur relief, leurs bâtiments et leurs arbres destructibles ; au Canyon, l'IA au sol suit les sentiers, les ponts et les tunnels pour passer d'un niveau à l'autre ; l'Île volcanique, avec sa lave, sa mer et ses routes de montagne, où l'IA trouve son chemin sur une grille de passage ; la Cité, ses immeubles, ses épaves et ses voitures qui explosent ; le Port, son eau profonde, son cargo et ses portiques.

## Organisation du code

| Dossier | Rôle |
|---|---|
| `src/shared/` | La simulation : physique, robots, destruction, IA, armes, et le protocole réseau. Aucune dépendance au navigateur : elle tourne aussi sur le serveur |
| `src/server/` | Le serveur de jeu multijoueur (Node, WebSocket) |
| `src/client/` | Tout ce qui est propre au navigateur : rendu 3D, HUD, clavier/souris, caméra, son, garage, et les langues (`src/client/i18n/`) |
| `crates/casse-sim/` | La simulation en cours de portage en Rust, compilée en WebAssembly (`npm run native`), module par module, chacun vérifié contre son TypeScript |
| `tests/` | Tests automatiques de la simulation (ils tournent dans Node, sans navigateur) |
| `index.html` | Balisage du HUD, du menu et du garage, chargement du jeu |

La simulation prévient le rendu de chaque changement (bloc détruit, morceau séparé, débris…) par des événements. Le rendu ne fait qu'afficher : en multijoueur, le serveur envoie ces mêmes événements avec les poses des corps, et le client les rejoue sur une réplique du monde. Le détail est dans `docs/architecture.md`.

## Déboguer depuis la console du navigateur

`window.__casse` donne accès à la partie en cours. Par exemple :

```js
__casse.bots.map(b => [b.profile.id, b.ai.mode])
__casse.pause(true)    // fige l'IA
__casse.sim(600)       // avance la simulation de 10 s d'un coup
__casse.spawnWave(["tank", "heli", "spider"])  // une vague avec ces robots-là
```
