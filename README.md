# Casse-Robot

*English · [Français](README.fr.md)*

Prototype of a game of destructible block robots, in the spirit of Robocraft, that runs in the browser.

- **Rendering:** Babylon.js 9.28 (`@babylonjs/core`)
- **Physics:** Rapier 0.21 (`@dimforge/rapier3d-compat`, WebAssembly included in the bundle)
- **Language and tools:** TypeScript, Vite, Vitest

## Play online

**https://wasabules.github.io/casse-robot/**: against the AI, the garage and the map editor, in the browser (preferably a recent graphics card and Chrome, Edge or Firefox). The page is republished on every push to `main` (`.github/workflows/pages.yml`).

Multiplayer needs a game server (`npm run server`, or `npm run share` to share it on the Internet, see below): in the "Multiplayer" menu, enter its address as `wss://` (a page served over https can't reach a server on `ws://`).

## Running the project

1. Install **Node.js 20 or newer**: https://nodejs.org (LTS version).
2. Open a terminal in this folder, then:

   ```bash
   npm install
   npm run dev
   ```

3. The browser opens on `http://localhost:5173`. Every time you save a file, the page reloads by itself.

| Command | Effect |
|---|---|
| `npm run check` | Checks the types and runs the tests: do it before every commit |
| `npm test` | Runs the tests once (`npm run test:watch` to rerun them on every change) |
| `npm run build` | Build to put online, in `dist/` (`npm run preview` to test it) |
| `npm run server` | Starts a multiplayer game server (port 8787); players connect to it through the "Multiplayer" menu |
| `npm run share` | Shares the game on the Internet: builds, starts the server and a Cloudflare tunnel, then shows the link to send |
| `npm run battle` | Eight AI-versus-AI battles without display, and a balance report per robot and per weapon (cost of a step, time robots spend stuck); an arena other than the Depot: `BATTLE_ARENA=canyon npm run battle` |
| `npm run bench` | Cost of a simulation step with twelve robots, stage by stage |
| `npm run perf` | Rendering measurement: the built game in headless Chrome on your graphics card, a twelve-robot battle, frame time stage by stage (`--compare` for a before/after) |
| `npm run render:check` | Rendering check (also in CI): every screen draws, without errors, and survives a graphics card reset |
| `npm run map:check` | Checks the community maps (those in `maps/`, or the given files and packages: `npm run map:check -- ma-carte.casse-map.json`) |
| `npm run map:terrain` | Imports a terrain (16-bit PNG, 16-bit RAW) into a map: see `docs/maps.md` |
| `npm run map:export -- all` | Writes the game's arenas as map files (`content/arenas/`, the files the game plays) |
| `npm run map:pack`, `npm run map:unpack` | Turns a map file into a map package (a folder: `map.json`, a 16-bit `terrain.png`, `LICENSE.txt`, and the map's own prop models and ambience) and back, and a package folder into one `.casse-map.zip` file to share, and back |
| `npm run schemas` | Regenerates the JSON Schemas of the map and robot formats (`schemas/`), of the element files (`content/schemas/`) and the content catalog (`content/catalog.json`) from the code |
| `npm run models` | Checks the glTF models of the props, blocks, turret heads and wheels (`public/models/`) and updates their manifest: see `docs/models.md` |

## Languages

The game speaks **French** and **English**: the language is chosen in **Settings → Profile → Language** (by default, the browser's; English for a language the game doesn't know yet), and the whole screen changes at once, without reloading the page. The names of robots, arenas, parts and weapons are translated too; keys that type a character keep the name from your keyboard (Z on an AZERTY keyboard).

**For translators:** each language is a folder of `src/client/i18n/locales/` (French, `fr/`, is the source language; English, `en/`, the best starting point), one file per part of the game (menus, HUD, garage, part info cards…). For a new language, copy `en/` into a folder named after its code (`de/`, `es/`…), translate the texts (never the keys nor the `{paramètres}` (parameters) in braces; plurals according to your language's rules), then declare it in `src/client/i18n/state.ts` and `src/client/i18n/locales/index.ts`. TypeScript flags any missing or extra key and any parameter that differs from the French, and `npm run check` verifies the rest; a language that is still incomplete shows in English wherever a translation is missing. The details (glossary, conventions) are in `docs/architecture.md`, section "Languages (i18n)".

## Community maps

Anyone can make their own map, **in the game, with the map editor** (main menu → **Map editor**), or by hand: a terrain imported from their terrain tool (Gaea, World Machine, Blender, terrain.party, Unity: a 16-bit PNG image or a 16-bit RAW), and game elements described in a JSON file (`.casse-map.json`): buildings that collapse, woods, rocks, low walls, bridges, containers, water (deep or not), lava, paths, capture zones, named places. The game checks it (clear spawn lines, zones the AI can reach, a reasonable number of elements), then plays it like its own arenas: the AI moves around it, the minimap draws it.

- **The map editor:** you start from a blank map, a map from the library ("Edit") or a file; you import a terrain (an image) and sculpt it with a brush (raise, dig, smooth, flatten); you place the game elements from a palette (houses, apartment blocks, woods, rocks, ramps, containers, props, scenery, zones, places, fumaroles, waterfalls, lava lakes), you trace paths, fences, lava flows and bridges point by point; the map can be set at night (Settings → Night: the moon, the stars, the lampposts and floodlight masts lit); you set the water, the sky, the ground, the limits, and you freely place both teams' spawn lines. What you see is what you play, with the map's problems shown where they are; **P** tries it out right away against the AI, and the pause menu takes you back to the editor, in the same state. Undo and redo, a draft kept on every change, saving to the library, export to `.casse-map.json` and of the terrain to 16-bit PNG. The details: [`docs/maps.md`](docs/maps.md#the-editor).
- **Playing a map:** **Play → a mode → the map** (those in `maps/` ship with the game). **Community maps… → Import a map…** adds one, kept in the browser; you can also export or delete it.
- **Map packages:** a map can bring its own glTF models for the game's props and its own ambient sound; it is then shared as one file, a `.casse-map.zip` package, which the game imports, plays and exports (the editor adds and removes these resources: **File → Resources**), and which a server plays. The details: [`docs/maps.md`](docs/maps.md#map-packages).
- **In multiplayer:** the server (`npm run server`) puts the maps in `maps/` into its rotation, after the game's arenas (`MAPS_DIR` for another folder, packages included, `MAPS_ONLY=1` to play only them; `ARENAS=valley,canyon`: only those game arenas); a player who doesn't have the map receives it once, and keeps it, with its resources (downloaded from the server by their SHA-256).
- **Making one:** the complete guide (the format field by field, importing a terrain, the limits, the tests, how to submit your map to the game through a *pull request*) is in [`docs/maps.md`](docs/maps.md). The example: `maps/val-du-lac.casse-map.json` ("Lake Vale": a lake, a river and its old bridge, a village, a farm, a ruin), and the script that made it, `tools/maps/example.ts`. A [JSON Schema](schemas/map.schema.json) gives autocompletion and checking in your editor (`"$schema"`: see the guide); robot designs have [theirs](schemas/robot.schema.json). The game's own arenas are written in the same format in `content/arenas/` (from the Depot to the Harbor), and the game plays them from there: a starting point, or a reference for what the format can say.

## 3D models and open data

- **3D models without code:** any prop (crate, barrel, tree, wall, car, street lamp…), any block of a robot (armor, cockpit, engine, turret base…), turret head and wheel can get a glTF model made in Blender: save it as `public/models/<family>/<type>.glb` (`props`, `blocks`, `heads`, `wheels`), run `npm run models`, and the game uses it instead of the model it draws, in matches, in the garage and in the previews (the crate shipped with the game is an example; an armor block takes the robot's color through its `paint` material, and wears like the others). The conventions are in [`docs/models.md`](docs/models.md).
- **The game's elements as data:** the game reads its blocks, wheels, weapons, melee weapons and props from one JSON file each, in [`content/blocks/`](content/blocks/), [`content/wheels/`](content/wheels/), [`content/weapons/`](content/weapons/), [`content/melee/`](content/melee/) and [`content/props/`](content/props/): to tune one, edit its file; its `$schema` gives completion and checking in your editor, and `npm run check` names the file and the field that are wrong. [`content/catalog.json`](content/catalog.json) lists every block, shape, wheel, weapon, melee weapon, prop and preset robot with its numbers and its names in French and English, documented field by field by [its JSON Schema](content/catalog.schema.json), for your tools, wikis and spreadsheets. It is generated from the code (`npm run schemas`).

## Loading

On startup, a loading screen prepares everything before the menu: the physics, all the sounds, the music (several tracks per screen, twelve in a match, chained with crossfades, none coming back before all have played; the title screen's music starts at the first click, without waiting) and the effects. Before each match, another screen builds the arena and the robots, prepares the match's effects and music, and only then does the match start: no stutter on the first shot or the first explosion.

## Playing together over the Internet

You need `cloudflared` (free, no account: `winget install --id Cloudflare.cloudflared` on Windows). Then:

```bash
npm run share
```

The game builds, the game server starts (it also serves the page) and a Cloudflare tunnel opens: a `https://….trycloudflare.com` link appears. Send it to your friends; everyone (you included) opens it, picks **Multiplayer** then **Pick my robot and join**: the server address is found automatically. The machine running `npm run share` hosts the match: it must stay on, and each player receives about 180 KB/s. The link changes on every launch; Ctrl+C stops everything. On the same network, the "Réseau local" (local network) address shown is enough (no tunnel). `npm run share -- --no-build` restarts without rebuilding.

## What's in it

**Playing**
- **Battle**: you pilot a robot on the blue team, six against six; the first team to fifteen kills wins, destroyed robots respawn on their own side. **Zone Capture**: take and hold zones A, B and C; each zone held scores points, the first team to a hundred wins. **King of the Hill**: a single zone in play, which moves every forty seconds; the first team to sixty wins. **Elimination**: no respawns. **Free Arena**: you watch two teams fight and shoot from a free camera. **Shooting Range**: the robots don't shoot.
- Ten arenas to choose from, plus the **community maps** (see above; **Lake Vale** ships with the game): the **Depot** (pillars, ramps, explosive barrels), the **Fortress** (a platform in the middle, four ramps up to it), the **Trenches** (three corridors separated by low walls), the **Construction Site** (two terraces on the flanks, containers in the middle) and the **Valley**, a large map more than 200 m across surrounded by mountains: terrain, a river spanned by a stone bridge, a village, a fort on its hill, a factory and its storage tanks, an airfield, woods. Everything there can be knocked down: walls fall in sections, roofs collapse when their walls have given way, trees topple, storage tanks explode in a chain. And two more just as big: the **Canyon**, a red desert split by a canyon with sheer walls, which you go down into by trails cut into the cliff, and cross by a wooden viaduct or by a natural arch on top of a mesa; a railway that runs through two buttes in tunnels, a Wild West town built of wood (saloon, church, water tower, station), a mine (headframe, spoil heaps, mine carts), an oasis at the bottom of the canyon, cacti. And the **Volcanic Island**: a tropical island ringed by the sea (you can drown in it), dominated by a volcano whose crater bubbles with lava; two switchback roads climb up to it; lava flows (which burn) run down to the sea, cut by a basalt ford; two gorges, with their waterfalls, are crossed on wooden bridges; a fishing village and its stilt huts, bunkers facing the open sea, a grass airstrip, the wreck of a freighter on the beach, and the jungle (palm trees, kapok trees), which burns. And the **City**, a ruined city for urban combat: streets and long avenues around a large square and its monument, an elevated expressway on its piers, a station whose tracks run along the bottom of a cutting, a park on its mound, a ruined tower and a multistory parking garage; its buildings collapse floor by floor, and its abandoned cars catch fire and then explode. **City by Night** is the same city under the moon and stars: its lampposts and floodlight masts lit (you can shoot them down to plunge a street into darkness), lit windows, and dark streets where it is the gunfire, the explosions, the flares, the fires and the robots' headlights that light up the facades. And the **Harbor**, by the sea: a freighter at the quay that you board by its gangways (a zone on its deck), container gantry cranes, a maze-like terminal, a swing bridge over the channel, a dock basin, oil depots whose storage tanks blow up in a chain, warehouses you can drive through, the railway, the fishermen's low quay and the lighthouses; the water there is deep, and whoever falls in drowns. In Zone Capture, five zones to take in the five large arenas.
- **Multiplayer**: run `npm run server` on a machine (or `npm run share` to play over the Internet, see above), then choose "Multiplayer" in the menu (the default address is that of the server serving the page, or in development the machine serving the page, port 8787). Players take the place of AI robots in an endless six-against-six battle, which changes arena with every match; the server is authoritative. It also keeps everyone's progress (file `casse-robot-progress.json`): credits earned on that server, parts unlocked there by joining with a robot from the garage.
- The controls follow those of **Robocraft** (default keys; ZQSD on an AZERTY keyboard, WASD on a QWERTY). By default, **the camera steers**: on the ground, ZQSD give a direction on screen and the robot goes there (Z: where you are looking); a flying robot turns to face where the camera looks; a **plane goes where you look** (with the mouse: it banks and pulls up on its own; looking up and keeping going makes it **loop**, go over on its back and come back), its **throttle separate** on Z and S (a target speed, shown on the flight panel; Shift: full throttle, X: cut), and on the keyboard Q and D make it turn, Space and C pull up and push down (held: a loop too). A setting ("Steering", "In a plane") switches to tank steering on the keyboard, and to **manual** piloting (the stick on the keyboard, unassisted: Space and C pull up and push down, Q and D roll, A and E are the rudder, Z and S the throttle; V switches in flight). The mouse aims (the turrets follow), click to fire, 1 to 9 to change weapon (a **spinner**, a **laser blade**, a **saw** or a **drill**, once selected, spins up on its own; a **hammer**, a **whip** or a **lance** strikes on the trigger; a **crusher field** has no key: it arms itself), **Space to brake** on the ground (wheels and tracks brake without skidding or tipping the robot over, hover pads and legs stop), Space and C to climb and descend in flight (released, the robot stops where it is), **Shift for boost** (boosters at full and wheel motors sprinting; it never brakes). Every key can be changed in the settings, the garage's included, and every help text, every info card names the ones you chose. A **gamepad** (Xbox, PlayStation) can be plugged in whenever you like: left stick to drive (in a plane: throttle and turning), right stick for the camera (in a plane: the direction), triggers to aim and fire, buttons for the rest; it also navigates the menus. The screen keeps only the essentials (score, weapons, robot status, minimap): **Tab** opens the scoreboard with both teams' robots (status, kills and deaths), the match and the controls (held, or pinned with a single press), and **M** the full map. Every robot can be piloted, the plane included; in flight, **A and E** control yaw, independently of roll: a drone or a helicopter turns on the spot while staying level, a plane makes a flat turn on the rudder, wings level, without sliding sideways (remote mines then move to G). Beyond the arena's limit, the plane turns back on its own. On a touch screen: a stick, fire and flight buttons, and a crosshair; you aim by swiping (as in a mobile shooter: one finger turns the camera, a second one doesn't make it jump) or, as a setting, with a second stick on the right, and you aim while firing by swiping from the Fire button; a pause button and full screen (where the browser allows it), an invitation to turn a phone sideways, and a HUD that makes room for the thumbs. The menus (as tiles across the width on a phone, so that they fit without scrolling) and the robot and arena screens work by touch, upright or sideways, and the first launch on a phone picks the lightest graphics. The garage and the map editor are made for a mouse: by touch they open and can be left, and say what needs a mouse.
- A **garage** to build your robot block by block (symmetry, orientation; fixed, steered or free-swiveling caster wheels, three separate parts, the steered one more expensive; wheels on the sides or under a block; tracks you can stack to make them taller or wider, with a single belt), within a budget of 600 points, with **shaped blocks** (wedges, corners, inner corners, rounds, gentle slopes, half blocks, in light or normal armor, wedge and corner also in heavy), whose physics has the shape you see: a ramp lets you climb, a wedge nose deflects impacts. A turret, a shape or a flare launcher orients itself according to the face you place it on (under a block, a turret hangs; on a side, it sticks out sideways); R rotates, Shift + R tilts, O turns off automatic orientation (like all garage shortcuts, they can be changed in the settings, and Ctrl+Z undoes on an AZERTY keyboard as on a QWERTY), and a preview shows the block as it will be placed (yellow arrow: the direction an engine pushes). There is also undo and redo, a layer view, copy and paste of a layer or a zone (Shift + click on two blocks), wheels that can be offset by half a cell, and the center of mass displayed; for a flying robot, its lift and endurance. The parts are in an **inventory**: categories in tabs, a search ("/"), 3D thumbnails, and each part's info card (what it's for, its stats, its rotating preview); 1 to 9 bring back recent parts, and the middle click copies the part you point at, orientation included: each left click places a copy of it. On the ground, a "FRONT" arrow and the robot's sides, and an on-screen compass, always tell you where the front is. You try it out, you save it, you pick it for battle. You can't place a part that would get in the way of another: a block in front of a turret's barrel, in a propeller's disk or a rotor's blades, on a wheel, against a turbojet's nacelle or a leg, under a bomb bay or behind a mine layer (nor the reverse); the preview turns red, showing transparently what the part occupies and what it would get in the way of, and the garage says why ("In the way of the barrel (Machine gun turret)"). A turret only reserves its rest pose, barrel straight ahead: a block next to its head only limits its field of fire. Propellers, rotors, nacelles and legs are drawn in the garage, in the preview and in the thumbnails as in the game.
- A **robot selection screen**: a grid of all robots (yours first) across the width of the screen, each card with its thumbnail, its propulsion, its weapons and its cost; filters (wheels, tracks, legs, hover pads, flying, planes, your garage), a search and a sort; and the info card of the selected robot (beside the grid, above it on a phone), with its rotating 3D preview, its mass, its speed and its weapons. The last robot chosen is highlighted. On the keyboard: the arrows move through the grid, Enter chooses; a gamepad too. And an **arena selection screen** in the same style: each arena, and each community map, with its map seen from above (terrain, water, lava, buildings and trees, the two teams' spawn lines, the capture zones), its description and a few facts (size, zones, day or night), and "Random".
- Synthesized sounds placed in space: shots, explosions, impacts, engines; a marker and a sound when your shots hit, an arc toward whoever is shooting at you.
- A **music player**: every track has its title ("Steel Titans", "Armored Neon"…); when one starts, a discreet note shows it for a few seconds. In the menus and the garage, a "now playing" line with **previous and next** buttons (also in Settings → Sound); in a match, **Page Down** and **Page Up** skip to the next or previous track (keys you can change). Previous goes back through the tracks heard on that screen, then next comes forward again.
- **Progression**: every piloted match earns credits (more for a win, kills, zones taken), which unlock parts in the garage; the basic parts are free. An "Every part" setting opens up the whole garage (sandbox).
- A **Settings** screen (from the main menu or the pause menu), applied immediately and kept in the browser. Graphics: the renderer (WebGL, or **WebGPU** where the browser offers it; taken when the page loads), low, medium or high preset, shadows and their detail, render scale, reduced effects, realistic or simple smoke and flames, field of view, frames-per-second counter. Controls: mouse sensitivity, inverted axes, scope held or toggled, steering by camera or keyboard, plane piloting by mouse or manual, the gamepad (right stick speed and axes, dead zone), and **your own keys**, on a screen of their own: one row per action (on the ground, in flight, weapons, interface, free camera, garage), two keys on the keyboard or mouse and one gamepad button; you click a slot, then press the new key (Esc cancels, right click clears; in the garage, a combination such as Ctrl+Z or Shift+R); a key already taken at the same moment moves to the other action as a swap, and ↺ restores the defaults. Touch (the first tab when you play with your fingers): aiming by swiping or with an aim stick, their sensitivities, inverted vertical axis, scope button toggled or held, size and opacity of the on-screen controls, left-handed layout, steering. The game's help texts name the keys you chose, according to your keyboard (Z on an AZERTY keyboard). Sound: on, volume. Profile: the game's language (French or English), name and multiplayer server.

**The robots**
- Each weapon has its accuracy: best when scoped and stationary, worse when driving, turning or pitching (a sniper on the move no longer hits anything); the crosshair shows the circle the shots will go into. The sniper's scope has its optics; with the cannon (and the EMP shell and smoke launchers), the player chooses the elevation by raising the mouse: the cannon points straight at the crosshair, the range depends on the elevation, and a diamond marks the expected point of impact; its panel shows the elevation, the heading, the range and the flight time; flying robots have an artificial horizon, altitude, speed and heading.
- Twenty-eight weapons, including the **laser** (continuous, precise fire that gets through heavy armor), the **railgun** (a streak that goes through several blocks) and the **plasma** (a scorching short-range jet): these three draw on the robot's batteries. The **shotgun** fires a spray of nine pellets, devastating at close range; the **rocket pod** empties its rack in one salvo of mini-missiles that fan out and converge on the aim point; **lock-on missiles** only launch once the enemy has been kept 1.2 s in the sight and in view (scenery or smoke hiding it breaks the lock), then chase it with momentum and weight: fired upward, they pass over a wall or a hill and dive onto it, and a sharp swerve at the right moment makes them miss; every missile first leaves straight along its weapon's axis before turning; the **piloted warhead**, a single shot per life, is steered with the mouse, the camera at its nose, and explodes on a click (or on contact) with an enormous blast, while its robot waits, motionless. Every shot recoils: the turret's head kicks back, and the pilot's view jumps up then comes back. Under a plane, a **bomb bay** drops a string of bombs as long as you hold the trigger: they fall keeping the plane's speed, whistling, and a circle on the ground shows where the next one will land. A **shield** absorbs part of the damage around it as long as the batteries hold. Nine **mines**, laid behind you: standard, EMP (stuns), incendiary, smoke, bouncing (bursts at crate height), anti-air (fires a missile at whatever passes overhead), remote (E sets it off), sensor (shows nearby enemies to its team, through walls) and sticky (sticks to the robot and bursts two seconds later), each with its own model and a light that blinks at its own rhythm once laid; an explosion sets off neighboring mines in a chain, and the AI steers around those it has spotted. The **repair beam** repairs allies, and drains life from enemies; **nanites** lock on by themselves to the most damaged ally and repair it from afar, without aiming; the **barrier projector** deploys an energy wall in front of you that stops enemy fire; and repair (module, beam, nanites) makes **lost blocks grow back**. A **flare launcher** (F key by default; the AI uses it on its own) ejects burning flares that divert enemy missiles; and missiles, rockets, bombs, mines and the piloted warhead can be shot down in flight: you aim at them with the crosshair, and the AI's automatic turrets fire at those rushing toward it.
- Shots you can see: missiles leave a smoke trail that draws their path (gray for the anti-air, whose burst leaves a black cloud; thick for the warhead; thin for rockets, whose fan you can see closing), a shot-down missile spins off, a decoyed missile flies off lost, sputtering; the sniper leaves a vapor wake, the railgun a crackling ionized streak; one rifle bullet in four is a tracer in the team's color; casings jump out of the breech, the muzzle smokes after a heavy shot, the cannon kicks up dust around the robot, the missile launcher spits a plume backward; the laser and plasma make what they hit glow red; the repair beam shows the life it drains (red streams toward the shooter) and the life it restores (green streams toward the ally), and nanites fly in a swarm.
- **Melee weapons**: a spinning mass has consequences. The **horizontal spinner** (a 1.9 m steel bar spinning flat in front of the robot) spins up in 2.4 s drawing on the batteries, keeps its energy and dumps it into whatever it hits: it rips off whole blocks, breaks fragile arms and throws its target, but every hit costs it spin and makes its own robot bounce; spinning, it makes the robot gyroscopic (it pitches up or down when it rolls sideways), and below half its hit points it becomes unbalanced: the whole robot vibrates, its aim and its wheels suffer, and it wears out until it breaks. A wedge glacis taken at an angle makes it glance off, heavy armor absorbs it, a low robot passes underneath. The **pneumatic hammer** slams down in front of the robot on the trigger, hits the top of its target hard and its own nose lifts with each blow. A gauge around the crosshair shows the spin or the rearming; sparks, debris, a whine that rises with the spin, a clang on impact. The AI charges at full spin and strikes when its head would hit. And **energy weapons**, massless: no gyroscope, no recoil, no imbalance, but they drain the batteries. The **laser blade** (an arc that sweeps flat in front of the robot, humming) lights up in half a second and cuts fast, in small strokes, through what heavy armor doesn't slow down; under an EMP or in water, it goes out at once. The **plasma whip** cracks from right to left in front of the robot and sets fire to what it touches. The **shock lance** thrusts straight ahead and stuns the components around the point it hits for 2.5 s (the wheels on that side freewheeling, a turret silent, an engine cut: the rest works; arcs run over them, and the HUD says what is cut). The **crusher field** arms itself when an enemy approaches: whatever touches the hull is struck and pushed back, and an enemy spinner that rubs against it loses its spin. The **circular saw** and the **drill** don't strike: they bite continuously into what they touch, their damage follows their spin, which drops under load, and they pierce one block then the next. The saw, small and fast, grabs: its grip pulls the robot along its target, so you drive it by skimming along it; a shallow glacis makes it glance off. The drill, a one-meter bit behind a gearbox, goes through a line of blocks all the way to the cockpit; its torque twists its target and, in reaction, makes a light robot roll over on itself: it needs mass or a wide footprint. Showers of sparks, metal shavings, a red-hot gash that cools down; the saw whines and grinds as it bites, the drill rumbles. The AI aims for the cockpit with the drill and pushes straight in, and skims along its target with the saw. And **mechanical strikes**: the **flipper** raises, with a stroke of its ram, a wedge-shaped plate slipped under the enemy and throws it into the air (the enemy gets hurt landing); the ground holds up the one doing the lifting, but a light robot trying to lift a heavy one sinks and noses down. The **flail** swings a spiked ball on the end of a chain: a real pendulum, which hits all the harder the faster it goes (four times as hard at twice the speed), follows turns poorly and tugs at its robot on every turn, bounces and wraps around a post. The **crusher jaw** grabs what enters its mouth, crushes it and drags it backward; it is the heavier one that doesn't move: a light robot that bites a heavy one only hangs on to it. It lets go when you release the trigger, after six seconds, or when the prey pulls too hard. And the spinner family: the **vertical spinner** (a thick disk standing upright at the front) scoops up the opponent from below, lifts it and flips it over; if it noses down and bites the ground, it is its own robot that does a backflip; the **drum**, low and wide, makes its target hop with small hits and rips off its wheels and rollers; the **shell spinner** spins around the whole robot, hits from every side without aiming and serves as its armor, but turns it into a huge gyroscope that skids when the ring picks up speed again. And a plane's **propeller** is sharp: its 2 m disk wounds whatever it grazes, but breaks on it, and the engine with it. The blades and heads of melee weapons can be hit: a shot on the bar, the disk or the ring hits the weapon.
- 46 preset robots, including the Reaper (horizontal spinner), the Pounder (pneumatic hammer), the Duelist (laser blade and shock lance), the Urchin (crusher field and plasma whip), the Sawyer (circular saw), the Borer (drill, on a wide tracked chassis), the Catapult (flipper), the Crusher (crusher jaw), the Thresher (flail), the Tumbler (vertical spinner), the Drummer (drum) and the Whirlwind (shell spinner), three ships carved out of shaped blocks: the Frigate (an arrow-shaped ship on four thrusters, ventral laser), the Manta (a streamlined hovercraft, rockets and flamethrower) and the Bastion (a heavy tank with a wedge glacis and sloped skirts); and also: vehicles on suspended wheels, fixed or steered (Ackermann geometry), a tracked tank, a hovercraft on hover pads, a spider on six articulated legs, a drone and a hexacopter with rotors, a helicopter with a tilt rotor and a tail rotor, a plane with wings and control surfaces, a rocket car, a shield-and-laser box (Bulwark), a railgun hunter (Lancer), and those of the new weapons: Brawler (shotguns, it charges), Swarm (rockets), Tracker (lock-on missiles and radar), Furnace (plasma), Warhead Carrier (piloted warhead), Bomber (bomb bays: the AI makes passes over its targets), and classes: Sapper (EMP, sticky and bouncing mines sown around its target), Mechanic (heals its allies by circling them), Guardian (energy wall and repair beam), Angel (nanite drone), Scout (sensors and anti-air mines), Fighter (two turbojets) and Dragster (four turbojets on wheels). The planes have real propellers, which spin according to the throttle; the **turbojet**, which you can place anywhere and facing any way, pushes five times harder than a booster, with a long afterburner flame.
- Real propulsion physics: wheel torque and load, suspension, rotor thrust, wing lift, and energy: thrusters drain the batteries, a drone has to land to recharge.
- Blocks of varying toughness, with resistances: heavy armor shrugs off bullets, reactive armor explosions. Thin necks and arms one block wide can snap under an impact. Collisions do damage: ramming a wall at full speed, or a light robot, costs blocks.
- A robot is out of action when its cockpit is destroyed, or when only a quarter of it is left around the cockpit. Flipped over, it is set upright by the cockpit's gyroscope after three seconds.
- Damage you can see: damaged blocks scorch, get stained and smoke, blacken with soot after a fire or an explosion; hit batteries and shields crackle; a robot on its last legs goes up in flames, its torn-off parts smoke as they fly and its wreck leaves a column of smoke; damaged wheels smoke, their wrecks burn; a gun that heats up glows red then smokes. On the ground: tire and track marks that fade, dust when skidding, splashes of water in the river, footprints and dust from legs, a ring of dust on a hard landing, sparks from impacts.
- Equipment: batteries, repair module, radar (it sees through walls), jammer, and lights, placed on top, underneath or on a side: the **headlight**, which lights straight ahead of the face you place it on, the **beacon**, which glows in its team's color, aircraft lights (the **navigation light**, red on the left and green on the right, the **strobe light**, a white strobe, the **anti-collision light**, red, which rotates), the orange **rotating beacon**, whose beam sweeps the walls, and the **police light bar**, blue and red in alternation. They shine by day as by night, and at night they light up their surroundings. The Truck and the Ram drive with their headlights on, the Drone carries a beacon.
- Engines that can be damaged: a hit engine loses thrust, misfires, smokes, then belches black smoke and can catch fire; a plane whose engine is spent glides and lands.
- Engines that burn: behind the nozzle of a thruster, a booster or a turbojet that is pushing, a jet of flame (1 m for a thruster, more than 4 m for a turbojet on afterburner) heats what it touches: the blocks and wheels of an enemy robot (which can catch fire), those of its own robot if it is badly built (the garage warns about a block placed in an engine's jet), the wooden scenery, which goes up in flames, a barrel, which blows up. A fleeing Dragster burns its pursuer, and the AI of a robot with boosters fires them up on an enemy stuck to its rear. Where the jet hits, flickers of flame spread out, the surface glows, the ground scorches and blocks blacken with soot.
- Flight effects: afterburner, contrails, wingtip vortices, dust raised by rotors, blurred propeller disks, exhaust from accelerating robots, electric arcs on a stunned robot, a downed plane falling in smoke.

**Combat**
- Realistic smoke and flames ("Smoke and flames" setting: realistic, except at the low preset): smoke is made of textured billows, lit by the sun (lighter on the sun side, darker underneath), which roll, fray and fade out just above the ground; a smoke grenade makes a real thick cloud that spills over and really hides what it covers (from inside, you can't see more than a few meters); flames ripple as they rise, from white-yellow to red; an explosion is a rolling fireball that blackens into smoke and throws up dirt; the flamethrower spits a jet of fire; engine flames stream and flicker, bluish at the core for a turbojet on afterburner.
- The scenery reacts: wood (cabins, roofs, trees, crates) catches fire, blackens, spreads the fire to its neighbors and collapses; the flamethrower and the incendiary mine leave pools of fire on the ground (water puts them out); an explosion leaves a crater, a scorch mark, smoke that keeps rising, embers that fall back, and makes trees bend; a punctured gas cylinder spits its gas, a barrel's fuse crackles, ruins smoke. As options (Graphics tab): a glow around whatever shines, **dynamic lights** (dozens at once, if the graphics card allows it: explosions, gunfire, missiles, tracers, flares, plasma, fires, engine flames and energy weapons light up the ground and walls around them; at night, it really shows) and air that shimmers above fires and behind nozzles.
- 9 weapons with physical projectiles, on turrets independent of the robot: auto rifle (overheats), piercing sniper, cannon, guided missile, anti-air missile, mine, flamethrower (fire spreads), electromagnetic pulse cannon (it cuts engines and turrets: a drone falls), smoke launcher (it blocks sight). Magazines, ballistics, recoil, penetration, explosions. Several identical weapons fire in turn, faster and faster, but each additional weapon speeds up the rate of fire less than the previous one (two rifles: ×1.8, four: ×2.95).
- The AI fights at its weapons' range (the flamethrower up close, the sniper from afar) by circling its opponent, takes cover behind a pillar to reload or repair, finishes off damaged robots and picks its targets according to what its weapons can pierce. It steers around obstacles, only targets what its team has spotted (by sight or radar), lands to recharge its batteries, covers its retreat with smoke, and aims worse at a target that maneuvers.
- The kill feed says who destroyed whom, and with what.
- 72 × 72 m arenas with ramps, pillars, and props: crates, explosive barrels (in a chain), gas cylinders that fly off when punctured; the Valley and the Canyon, with their terrain, their destructible buildings and trees; in the Canyon, the ground AI follows trails, bridges and tunnels to get from one level to another; the Volcanic Island, with its lava, its sea and its mountain roads, where the AI finds its way on a nav grid; the City, its buildings, its wrecks and its exploding cars; the Harbor, its deep water, its freighter and its gantry cranes.

## Code layout

| Folder | Role |
|---|---|
| `src/shared/` | The simulation: physics, robots, destruction, AI, weapons, and the network protocol. No browser dependency: it also runs on the server |
| `src/server/` | The multiplayer game server (Node, WebSocket) |
| `src/client/` | Everything specific to the browser: 3D rendering, HUD, keyboard/mouse, camera, sound, garage, and languages (`src/client/i18n/`) |
| `crates/casse-sim/` | The simulation being ported to Rust, compiled to WebAssembly (`npm run native`), module by module, each checked against its TypeScript; in the probe (`npm run native -- --probe`), the simulation that owns its Rapier world already drives the ground robots and crashes them (destroyed blocks, broken links, split parts, torn-off wheels) into each other and into the props (crates that break, barrels that explode in a chain, gas cylinders that vent and fly off, trees felled, walls broken through, fire) to the bit |
| `tests/` | Automated tests of the simulation (they run in Node, without a browser) |
| `index.html` | Markup for the HUD, the menu and the garage, game loading |

The simulation notifies the renderer of every change (block destroyed, part split off, debris…) through events. The renderer only displays: in multiplayer, the server sends these same events along with the poses of the bodies, and the client replays them on a replica of the world. The details are in `docs/architecture.md`.

## Debugging from the browser console

`window.__casse` gives access to the current match. For example:

```js
__casse.bots.map(b => [b.profile.id, b.ai.mode])
__casse.pause(true)    // fige l'IA
__casse.sim(600)       // avance la simulation de 10 s d'un coup
__casse.spawnWave(["tank", "heli", "spider"])  // une vague avec ces robots-là
```
